# Calendar Bridge: рабочий календарь ↔ Google Calendar ↔ Calendly

Пост в канале: https://t.me/technosurvival/<NNN>

Комплект из трёх частей, которые вместе дают единый календарь занятости:

1. **Сервер** (Python/FastAPI) принимает снимок рабочих встреч с телефона
   и раскладывает его в Google Calendar без дублей.
2. **Макрос MacroDroid** раз в 30 минут читает рабочий календарь Exchange
   и отправляет снимок на сервер по HTTPS.
3. **Google Apps Script** переносит брони Calendly в рабочий календарь
   через приглашения по почте — с корректной обработкой переносов и отмен.

```
Exchange (телефон)                 Calendly
      │ MacroDroid                     │ пишет брони
      │ HTTPS POST /sync               ▼
      ▼                          Google Calendar «Calendly»
  Caddy (TLS)                          │ Apps Script (каждые 5 мин)
      │                                 │ копия + приглашение
      ▼                                 ▼
  FastAPI ──► Google Calendar ◄── календарь «Личные брони (авто)»
              «Рабочий календарь»           │
                    │                       │ приглашение на рабочий адрес
                    └──────► Calendly (занятость) ◄── Exchange (Outlook)
```

## Что где лежит

| файл | назначение |
|---|---|
| `server/app/matcher.py` | вся логика сверки: дубли, переносы, отмены, защита от массового удаления |
| `server/app/sync.py` | разбор снимка и применение операций в Google |
| `server/app/google_cal.py` | клиент Google Calendar (сервисный аккаунт) + in-memory заглушка для тестов |
| `server/app/main.py` | HTTP API: `/sync`, `/status`, `/healthz`, `/macro` |
| `server/app/caddy.py` | добавление маршрута в работающий Caddy через admin API (без root) |
| `server/tests/` | 22 теста на сверку и сквозные сценарии |
| `server/tools/make_macro.py` | генератор `.macro` из шаблона |
| `macrodroid/calendar_bridge.macro` | файл для импорта в MacroDroid |
| `google-apps-script/calendly_to_work_calendar.gs` | скрипт Calendly → рабочий календарь |

## Быстрый старт

```bash
# 1. зависимости
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# 2. конфигурация
cp .env.example .env
# SYNC_TOKEN — 32 случайных байта: openssl rand -hex 32
# CALENDAR_ID — id календаря из настроек Google Calendar
# GOOGLE_SA_JSON — путь к ключу сервисного аккаунта
# DOMAIN — ваш домен, указывающий на сервер

# 3. запуск (без root)
./service.sh start

# 4. макрос
.venv/bin/python tools/make_macro.py   # соберёт .macro с вашим токеном и доменом
```

Установка как systemd-сервиса (переживает перезагрузку): `sudo deploy/install-root.sh`.

## Развёртывание остальных частей

### MacroDroid (телефон)

1. Установи MacroDroid — нужно действие «Get Calendar Events», оно появилось в версии 5.57.
2. Сгенерируй макрос со своим токеном и доменом: `.venv/bin/python tools/make_macro.py`.
3. Импортируй полученный `macrodroid/calendar_bridge.macro` в MacroDroid.
4. Открой действие «Get Calendar Events» и выбери свой рабочий календарь Exchange.

### Google Apps Script (Calendly → рабочий календарь)

1. Открой Google Apps Script (script.google.com), создай проект.
2. Скопируй содержимое `google-apps-script/calendly_to_work_calendar.gs`.
3. Подставь константы вверху файла: `SOURCE_CALENDAR_ID` (календарь, куда пишет Calendly) и `WORK_EMAIL` (рабочий адрес).
4. Включи Calendar API: Services → «+» → Calendar API.
5. Один раз запусти `installTriggers()` — скрипт начнёт выполняться каждые 5 минут.

### Calendly

Подключи Calendly к Google Calendar и включи проверку занятости по всем календарям аккаунта — тогда рабочие встречи, зеркалированные в Google, автоматически блокируют слоты.

## Как работает сверка

Телефон присылает **полный снимок** окна (14 дней вперёд). Каждый цикл сервер
сравнивает его с тем, что уже создано в Google:

1. точное совпадение «название + начало» → ничего не делаем;
2. изменилась длительность → правим конец;
3. то же название, другое время (разница ≤ 21 дня) → перенос (patch);
4. то же начало, другое название → переименование;
5. остаток → новое событие;
6. пропавшие события → удаление.

Правила удаления:

* одиночные пропажи (до 3 за цикл) удаляются сразу — чтобы слот освобождался
  за один цикл;
* массовые исчезновения требуют двух подтверждений подряд;
* если снимок пуст или событий стало меньше половины при 5+ существующих,
  удаления в этом цикле блокируются полностью.

Каждое созданное событие помечено `extendedProperties.private.bridgeSync=1`,
поэтому чужие события в календаре не затрагиваются. Прошедшие встречи
не удаляются — остаются историей.

## Безопасность

* Наружу смотрит только Caddy с валидным TLS; приложение слушает `127.0.0.1`.
* Bearer-токен 32 байта, сравнение через `hmac.compare_digest`.
* Лимит 60 запросов / 10 минут с IP, тело ≤ 256 КБ, ≤ 500 событий.
* В логи пишутся только счётчики и хеш IP — ни названий, ни времени встреч.
* `.env`, ключ сервисного аккаунта и SQLite — права `600`, umask `077`.
* Сервисный аккаунт имеет доступ только к одному календарю, который ему явно
  расшарили.

## Грабли, на которые мы наступили

**1. MacroDroid при выводе в словарь не кладёт поле `Title`.**
Название становится ключом записи, а к дублям дописывается номер
(«Планёрка 2»). Пришлось восстанавливать название из ключа и склеивать
хвостовые номера.

**2. Отменённые встречи Exchange остаются в календаре.**
Они приходят как обычные события с темой `Canceled: …`. Добавлен фильтр
по префиксам (`Canceled:`, `Cancelled:`, `Declined:`, `Отменено:` …).

**3. Scope `calendar.events` недостаточно.**
На `calendars.get` приходит 403 «insufficient authentication scopes».
Нужен полный `https://www.googleapis.com/auth/calendar`.

**4. Calendly не удаляет отменённую бронь.**
Он оставляет событие со статусом `confirmed` и переименовывает его
в `Canceled: …`. Отмену приходится ловить по трём признакам: удаление,
`status=cancelled`, префикс в теме.

**5. В Apps Script порядок аргументов неочевиден.**
`Calendar.Events.insert(resource, calendarId, options)` — тело события
идёт первым. Если передать id календаря первым, Google отвечает
`Bad Request` без подробностей.

**6. Удаление «после двух пропусков» даёт до часа задержки.**
Из-за этого слот в Calendly оставался занятым после отмены. Одиночные
отмены теперь применяются сразу.

**7. Приглашение на рабочий адрес Outlook добавляет сам.**
Exchange создаёт события из писем-приглашений с темой вида
`Invitation: … @ …`. Это и есть канал обратной блокировки — писать
в рабочий календарь напрямую не нужно.

## API

```
POST /sync        Authorization: Bearer <token>
                  тело: JSON-массив событий или объект MacroDroid
GET  /status      с токеном: статистика и последние запуски
GET  /healthz     без авторизации: {"ok":true}
GET  /macro?t=…   выдача .macro файла по токену
```

Формат события (компактный):

```json
{"s": 1793600000000, "d": 30, "t": "Планёрка"}
```

Поддерживается и «сырой» вывод действия Get Calendar Events
(`Title`, `Start Timestamp`, `Duration Minutes`, `All day event`).
